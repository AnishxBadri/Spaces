# Dead code — 2026-10-11

Read-only audit of main `a5ae157`. Nothing was deleted. knip 5.88.1 ran with
`corepack pnpm dlx knip@5 --config <scratch>/knip.json` (compact and json
reporters) in two modes: **full**, where tests count as usage, and
**`--production`**, where only the `!` entries count. Something flagged in
production mode but not in full mode is used only by tests. Every candidate
was then grepped across the repo, excluding `node_modules`, `dist`,
`.output`, `.turbo` and `routeTree.gen.ts`. Three hand passes covered what
knip can't see: server fns with no UI caller, queues nothing enqueues, and
component props no caller passes. Also checked: `workspace.settings` keys,
CSS utilities and custom properties, and doc paths that no longer exist.

**Not covered:** `apps/site` beyond what knip reports, jsonb fields other than
`workspace.settings`, and doc prose (only paths were checked against the tree).

**Two knip blind spots that the config works around:**

- `#web/*` does not resolve across workspaces. Every web module the worker
  imports through it looks unused. The config lists those modules as
  `apps/web` entries instead.
- `@spaces/sdk` resolves to `dist/`. knip can't see plugins using the SDK's
  source, so the SDK surface was checked by a TypeScript-API script instead.

## 4. Not dead, worth knowing

- Every `workspace.settings` key (`base_currency`, `sensitivity_default`,
  `ai_caps`, `embedding`, `logo`, `demo`, `enrichment`) has both a writer and a
  reader.
- Every other queue in `QUEUES` has a producer and a worker.
- Every `@utility` is used except `z-toast`, which is kept above.
- Props that are always left at their default (`DitherBlock.width/height`,
  `SectionHead.as`, `RecordPicture.size`, `TemplatePicker.label`,
  `CreateDealDialog.triggerLabel`, `TooltipContent.sideOffset`) are knobs, not
  dead code.

## 5. Recommendation: knip as a CI gate

Yes, as one more named step in `ci.yml` (`corepack pnpm dlx knip@5`, about
11 s), **after slices A–D land**. Run the full mode only. Production mode
flags the deliberate test seams by design, so it belongs in a periodic audit
like this one, not in the gate.

To make it quiet, add these to the config above:

```jsonc
{
  "ignoreDependencies": ["@spaces/config"],
  "ignoreIssues": {
    "apps/web/src/lib/arrival/input.ts": ["duplicates"],
    "apps/web/src/lib/settings-return.ts": ["exports"], // forgetAppPage, read through `typeof import()`
  },
  "workspaces": {
    "apps/web": { "ignoreDependencies": ["nitro", "@tailwindcss/vite"] },
    "apps/worker": {
      "ignoreDependencies": [
        "@spaces/plugin-*",
        "@ai-sdk/*",
        "@openrouter/ai-sdk-provider",
        "ollama-ai-provider-v2",
        "@tanstack/react-start",
        "better-auth",
        "imapflow",
        "mailparser",
        "pdf-lib",
      ],
    },
    "apps/site": {
      "entry": [
        "+ src/layouts/**/*.astro!",
        "+ src/components/**/*.astro!",
        "+ src/integrations/*.ts!",
      ],
    },
    "packages/db": { "ignore": ["src/schema/auth.ts"] },
    "packages/sdk": { "entry": ["+ src/pack/cli.ts!"] },
    "plugins/_fixtures/*": {
      "entry": ["+ src/v1.ts!", "+ src/v2.ts!", "+ vite.*.config.ts!"],
    },
  },
}
```

With these deltas, the full-mode run on `a5ae157` reports only entries from
slices A–D: 1 file, 7 dependencies, 30 exports and 5 types. Once the slices
land it is empty.

knip does not report part of the batch: `createHolding`, the
cascade handlers, the test-only entries, the dead props and the
`entity.enrich` queue. Those need a hand pass like this one.

The one maintenance cost is the worker-crossing entry list in `apps/web`. It
shrinks as `lib/` moves into core, and it should be kept in step with the
eslint worker zone's crossing list (`WORKER_NEVER_WEB_NEVER_PLUGINS`). A
crossing missing from the list shows up as a false "unused file", so the gate
fails loudly rather than silently.
