# UX walk 2026-10-11 · what each surface costs (main `a5ae157`)

How it ran: `@spaces/web` built at `a5ae157`, booted twice by the e2e screenshot harness (`apps/e2e/harness/screenshots-setup.ts`) against a throwaway `spaces_e2e_<pid>_shots` database seeded with the bench (`apps/web/src/db/seed.ts`, owner Anika Rao, workspace Harbour Lane), owner session, Chromium at 1440×900, one worker under `nice`. Every `_app` route (Today, Tasks, Spaces, a space and its five tabs, Notes, a note, Files, Companies, People, Deals and its board, Vehicles, Portfolio, a holding, a term, Mandate, Review, Import) and every settings page, top and scrolled, plus the states a user meets: each page head's `···` open, the file row `···` and the add-row `···`, the file viewer, Filter / Columns / Save view, Cmd-K empty, typed and asked a question, on Today and on a record, the keyboard sheet, the New company / person / deal (from the list and from a record) / space / object / invite / Record a check / Record a mark / Log interaction windows, Edit attribute, Enrich before and after pressing, a company created with only a name, an empty custom-object list, the collapsed sidebar. 179 screenshots and a JSONL of every head cluster's and dialog foot's controls with their computed style (fill, border, height, printed key) live outside the repo in `~/.claude/projects/-Users-anishbadri-Desktop-spaces/pass-harness/ux-walk-2026-10-11/` (`shots/`, `ux-log.jsonl`, and the two specs that took them). The harness runs no worker, so Enrich could not finish; that is noted where it matters.

This walk does not compare against the Paper sheets. It asks of each surface: what does this cost the user, and could the same capability cost less? Every proposal keeps the capability and changes where it lives, how often it is shown, or whether the user has to supply it. `against Dnn` marks a finding that runs into a closed decision.

Entry format: `U<n> · lens · what the user sees (shot) · what it costs · the simpler form, capability kept · effort · likely file`.

## 4. Proposed action grammar

Written for `docs/design-contract.md` §1, beside the Commentary Rule.

- **A1 · A page head carries one filled primary, at most one outline secondary to its left, and a boxed `···` at the far right.** All three are 32px. Nothing used less than weekly sits at rest; it is a `···` item. A head with no daily act has no filled button. (U10, U11, U12, U23, U24, U30, U79, U84)
- **A2 · No key is printed inside a button.** A key lives in the button's tooltip, the `?` sheet and Cmd-K. Keys print only in a composer row's end lane and in the sidebar lane, where they are the row's data. (U10, U75, U79, U101)
- **A3 · One act has one control per surface, and one label everywhere.** If a section has a composer row for a verb, the head does not also carry it; the key focuses the composer. The label is the same on every surface (`New task`, never `Task` / `Add task`). (U1, U34, U35, U36, U69)
- **A4 · A record head is `[verb] [verb] [···]` on every kind.** The verbs are the two most frequent for that object; Sensitive, Save as template, Copy link and Archive live in the `···`, which every record has. Navigation is a link in the title or crumb, never an outlined button. (U32, U33, U55, U66, U76)
- **A5 · A row ends on a mono lane and a bare `···`.** The lane holds the row's figure or state word; the `···` appears on hover; the row itself is the link. No word that would read the same on every row (`void`, `record mark ›`, `raised`), and delete is never a bare icon. (U3, U4, U5, U56, U62, U86, U118)
- **A6 · A dialog foot is `note? · Cancel · Primary`.** Cancel is outline, the primary is filled, neither carries an icon or a printed key. There is one commit; a variant is a toggle beside it. The note is for cost, privacy or irreversibility only, and it wraps rather than truncates. (U101, U102, U104, U106)
- **A7 · State is never a control.** No disabled button or menu item announces a missing setup; a `···` with no enabled item does not render; a menu of one item is that item as a button; a toggle shows its state as a switch, not as its label. Where something is missing, the place it would be used carries one link to fix it (D80). (U11, U22, U59, U60, U66, U105, U108, U110)
- **A8 · A number prints once per screen.** The title or the tab carries a list's count, not both; a readout never repeats a section count and a section never repeats a readout; a row prints a date or an age, not both. (U2, U13, U43, U61, U72, U80, U85, U91)
- **A9 · A create window asks only for identity.** Name plus the identity key (domain, email); everything else is `More fields ›`, inferred (company from email, deal name from company and stage, date today) or filled later by enrichment. Focus lands in the first field. (U58, U92, U97, U98, U99)
- **A10 · One tab bar shape, and it hides when there is one view.** Paper tabs with a count on every tab, Filter Sort Columns and search to the right; a second axis is a chip in that bar, never a second row; the bar is absent when there is a single view. (U14, U15, U65, U84)
